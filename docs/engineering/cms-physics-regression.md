# CMS resonance regression suite

The CI gate re-fits a compact, frozen set of CMS data candidates. It covers the
Z template closure, the J/ψ and Υ(1S, 2S, 3S) peaks, and the J/ψ dimuon mass
resolution in three muon-|η| bins. Run it offline with:

```powershell
uv sync --extra analysis --extra dev
uv run python tools/build_cms_resonance_validation.py `
  --from-pairs src/heplab/data/reference/cms-resonance-selected-pairs.json `
  --provenance src/heplab/data/reference/cms-resonance-data-report.json
uv run python -m pytest tests/test_cms_physics_validation.py -q
```

To refresh the low-mass fixture from CERN Open Data, omit `--from-pairs`. The
builder verifies the complete ROOT file's advertised Adler-32 and file size,
applies the checked-in 2016 golden-lumi JSON, reads the first 100,000 events,
and writes the selected pairs and fit report under
`artifacts/cms/resonance-validation/`. Keep the refreshed pair file and report
together; the report records the source checksum, certification checksum,
trigger paths, environment lockfile hash, dirty-tree state, and selected-pair
SHA-256. The report also includes a deterministic hash of the fitted physics
results (floating outputs are quantized to six decimal places before hashing
for cross-platform parity). A container digest is recorded as null for a host
execution.

The compact Z template inputs are regenerated by
`uv run python tools/calibrate_cms_mass.py` after its source ROOT inputs are
available under `artifacts/cms/measured/`. That command writes the selected
training/held-out masses to `cms-z-template-candidates.json`; CI then reruns
the fit, bootstrap, and closure from that package fixture without downloading
the source files.

## Inputs and selection

The low-mass source is the first 100,000 entries of one 2016G CMS DoubleMuon
NanoAOD file (Open Data record 30522). The frozen file contains one selected
opposite-charge pair per event and resonance. Pairs require both muons to have
`pT >= 2 GeV`, `|η| < 2.4`, a certified run/lumi section, and at least one
recorded low-mass trigger from the appropriate J/ψ or Υ trigger group. If an
event has multiple candidates in the target mass window, the builder keeps the
candidate closest to the PDG mass. It retains the two muon |η| values for the
resolution fits.

The stored sample has 3,355 J/ψ pairs, 599 Υ(1S), 335 Υ(2S), and 239 Υ(3S)
pairs. The Gaussian-plus-exponential peak fit gives approximate means of
3.08998, 9.45020, 10.02909, and 10.34000 GeV respectively. For J/ψ the fitted
mass resolution is about 27, 48, and 64 MeV across `|η| < 0.9`,
`0.9 <= |η| < 1.7`, and `1.7 <= |η| < 2.4`. These are small-sample regression
measurements, not precision CMS results.

The Z input is a frozen set of selected data and DY simulation masses, split
into training and held-out populations. CI reruns the template fit, a
deterministic 20-replicate bootstrap, and finite-template held-out closure. Its
gate checks the held-out closure against the predeclared p-value and expected
bin-count requirements. The raw reconstructed Z peak is recorded as a
diagnostic and is not compared directly to the precision CMS Z mass: this
selection has no Rochester or precision-scale correction and includes final
state radiation. The Z fit is a conditional spectrum comparison, not a
momentum calibration.

## Published references and tolerance bands

- The data source, run range, certified-run links, and processing metadata are
  listed in the [CMS DoubleMuon Run2016G NanoAOD record](https://opendata.cern.ch/record/30522).
- J/ψ mass-scale and resolution-versus-|η| guardrails are broad envelopes
  digitized from [CMS-PAS-MUO-21-001, Figure 17](https://cms-results.web.cern.ch/cms-results/public-results/superseded/MUO-21-001/index.html).
  The published points are not tabulated values, and the collision conditions
  and selections differ from this sample.
- The [CMS Z-mass result SMP-23-002](https://cms-results.web.cern.ch/cms-results/public-results/publications/SMP-23-002/index.html)
  is recorded as context. Its precision mass is not used as a direct pass/fail
  target for this uncorrected raw spectrum.
- The broad Υ(1S) resolution band spans the published central and inclusive
  values described in the [CMS Υ result](https://cms.cern/news/first-measurement-upsilon-production-7-tev-lhc).

Peak-mass tolerances are fixed in
`src/heplab/data/reference/cms-resonance-validation.json`. The three J/ψ
resolution intervals are likewise fixed there. Passing the gate means the
frozen data regression is consistent with those guardrails; it does not
validate the detector simulator or establish a new CMS measurement.

## Limits

This is one short entry range from one 2016G file. It has no trigger-object
matching, full-sample efficiency corrections, Rochester corrections, or
systematic uncertainty model. The J/ψ |η| intervals compare against broad
plot-digitized bands from a different CMS analysis. The reported Fisher errors
are approximate and omit background-fit uncertainty. The Υ peaks use separate
mass windows and a single Gaussian signal component; line-shape systematics
and feed-down are not modeled. Expanding the sample and harmonizing the CMS
selection and fit models remains necessary before calling this a full
experimental validation.

# Product and information architecture

## Purpose

The public project guide helps visitors understand what HEPLab currently does,
how to run it locally, what evidence supports its claims, and where its limits
are. It is a documentation site. It does not run simulations or access user data.

## Audiences

- Students and researchers learning what the project implements.
- Developers evaluating the code or contributing changes.
- Local users setting up the simulator and analysis tools.
- Reviewers checking the scope and provenance of scientific claims.

## Navigation

The Starlight sidebar groups pages by the questions visitors are likely to ask:

| Section | Pages | Visitor question |
|---|---|---|
| Start here | Overview, getting started | What is HEPLab, and how can I run it? |
| Project | Capabilities, roadmap, limitations | What works today and what remains open? |
| Use HEPLab | Workbench, models, Open Data, analysis | How does the local workflow operate? |
| Evidence | Validation records, interpreting results | What does the evidence show, and what does it not show? |
| Reference | Architecture, API boundary, contributing, FAQ | Where are the technical details and contribution steps? |

The engineering handbook remains the canonical source for detailed scientific
contracts, algorithms, and validation records.

## Acceptance

- A new visitor can distinguish implemented software from planned work.
- A reader can find local setup and the analysis workflow.
- A reader can find supporting evidence and understand its limits.
- A contributor can find the repository's development guidance.
- The guide remains useful as a static site without a running simulator service.
